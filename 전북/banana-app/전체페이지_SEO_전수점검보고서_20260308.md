점검 대상: `https://bananajeonju.netlify.app`  
점검 범위: 라이브 `sitemap.xml`에 선언된 전체 URL 전수 점검 + 비존재 URL 예외 점검 + 로컬 코드 원인 분석

## 1. 결론

- 라이브 사이트의 `robots.txt`와 `sitemap.xml`은 현재 접근 가능합니다. 사이트맵 파일 자체가 깨진 상태는 아닙니다.
- 치명 이슈는 `사이트맵 없음`이 아니라, `soft 404`와 `잘못된 사이트맵 URL 포함`입니다.
- 우선순위는 `1) soft 404 제거`, `2) sitemap에서 /404 /500 제거`, `3) 실배포와 로컬 코드 불일치 해소`입니다.

## 3. 확인된 사실

### 3-1. robots.txt

- `https://bananajeonju.netlify.app/robots.txt`는 `200 OK`
- `Sitemap: https://bananajeonju.netlify.app/sitemap.xml` 선언 존재

### 3-2. sitemap.xml

- `https://bananajeonju.netlify.app/sitemap.xml`는 `200 OK`
- `Content-Type: application/xml`
- XML 구조 정상
- `<loc>` 기준 라이브 URL 4,861개 확인

### 3-3. 사이트맵 전수 점검 결과

- 전체 4,861개 중 4,859개는 최종 `200`
- 아래 2개는 사이트맵에 포함되어 있지만 실제로는 `404`
  - `https://bananajeonju.netlify.app/404/`
  - `https://bananajeonju.netlify.app/500/`

### 3-4. soft 404 재현

다음 URL은 실제 존재하지 않지만, 최종 응답이 `200 OK`입니다.

- 테스트 URL: `https://bananajeonju.netlify.app/this-should-404-12345/`
- 확인 결과
  - 상태코드: `200`
  - title: `전주시 전북 배관막힘 긴급출동 | 지역업체 안내`
  - canonical: `https://bananajeonju.netlify.app/`
  - robots: `index, follow`
  - 본문에는 `Page not found` 표시 존재

즉, 검색엔진은 이 페이지를 오류 페이지가 아니라 인덱스 가능한 정상 문서로 오인할 수 있습니다.

## 4. 주요 문제 목록

### P0-1. 비존재 URL이 404가 아니라 200으로 응답함

증상:
- 임의 비존재 URL이 `200`
- 홈 title/canonical을 상속
- `Page not found` 텍스트만 본문에 표시

영향:
- 네이버/구글이 soft 404로 판정할 수 있음
- 저품질 문서 신호 누적 가능
- 색인 예산 낭비 및 전체 사이트 품질 저하 가능

원인:
- 동적 라우트 파일에서 데이터가 없을 때 `notFound()`를 호출하지 않고 직접 JSX를 반환함

원인 파일:
- `src/app/[id]/page.tsx`

### P0-2. sitemap에 /404 와 /500 이 포함되어 있음

증상:
- `sitemap.xml`에 `/404/`, `/500/` 포함
- 두 URL은 실제로 `404`
- canonical은 홈(`/`)으로 잡힘

영향:
- 네이버 서치어드바이저 품질 진단 악화
- 사이트맵 신뢰도 저하
- 검색엔진에 “색인 대상이 아닌 URL”을 반복 제출하는 상태

원인:
- 숫자 ID 기반 사이트맵 생성 로직이 `404`, `500`을 일반 페이지 ID로 포함
- Next.js/정적 배포 환경에서는 `/404`, `/500`이 예약 경로와 충돌

원인 파일:
- `scripts/generate-sitemap-numeric.js`
- `public/sitemap.xml`
- `src/utils/pageData.ts`

### P1-1. 라이브 배포물과 현재 로컬 코드가 일치하지 않음

확인 내용:
- 라이브 sitemap URL 수: `4,861`
- 로컬 `public/sitemap.xml` URL 수: `4,321`
- 라이브 홈 `naver-site-verification`: `2c62c37367623970724807466ebf77a83445582e`
- 로컬 `src/app/layout.tsx`의 `naver-site-verification`: `738a164c1756d77b0023eaab1092de55036f6a72`

영향:
- 현재 로컬 수정만으로는 라이브 문제를 정확히 재현하지 못할 수 있음
- 배포 후에도 의도와 다른 메타/사이트맵이 남을 수 있음

판단:
- 실배포가 현재 워크스페이스와 다른 빌드 결과를 사용 중일 가능성이 큼

### P1-2. 하드코딩된 사이트 URL이 남아 있음

확인 내용:
- `src/app/[id]/page.tsx`에 `https://bananajeonju.netlify.app` 하드코딩
- `src/app/layout.tsx`에 동일 URL 하드코딩 다수
- `public/robots.txt`도 고정 URL 사용

영향:
- 도메인 교체, 멀티사이트 운영, Netlify 프리뷰/실배포 분기 시 메타 신호가 쉽게 꼬임

### P2-1. 도메인/브랜드명과 실제 지역 데이터의 일관성이 약함

예시:
- 홈은 `전주시 전북` 중심 시그널
- 실제 상세 페이지는 `강원특별자치도`, `전라남도` 등 광범위 지역 포함

영향:
- 로컬 SEO 관점에서 주제 일관성이 약해질 수 있음
- 특정 지역 전문 사이트로 인식되기 어려움

## 5. 코드 원인 분석

### 5-1. soft 404 발생 코드

`src/app/[id]/page.tsx`

- `generateMetadata()`에서 `!pageData`일 때 빈 객체 반환
- 페이지 컴포넌트에서 `!pageData`일 때 `return <div>Page not found</div>;`

이 구조 때문에 Next.js의 정식 404 처리 흐름으로 들어가지 않습니다.

### 5-2. /404, /500 포함 원인

`scripts/generate-sitemap-numeric.js`

- `idCounter = 1`부터 순차 번호 URL 생성
- 예외 ID 제외 로직이 없음
- 결과적으로 `/404`, `/500`이 일반 문서처럼 사이트맵에 들어감

`src/utils/pageData.ts`

- 동일하게 순차 ID를 페이지 ID로 사용
- 예약 경로 충돌 방지 로직 없음

## 6. 권장 조치

### 즉시 수정

1. `src/app/[id]/page.tsx`
- `!pageData`일 때 `notFound()` 호출

2. `scripts/generate-sitemap-numeric.js`
- `/404`, `/500` 예약 ID 제외
- 가능하면 숫자 ID 대신 충돌 없는 slug 체계로 전환 검토

3. `public/sitemap.xml`
- 재생성 후 `/404`, `/500` 제거 확인

### 배포 전 정리

4. `src/app/layout.tsx`, `src/app/[id]/page.tsx`, `public/robots.txt`
- 사이트 URL을 환경변수 기준으로 통일

5. 실배포와 로컬 메타 설정 일치 검증
- `naver-site-verification`
- sitemap 개수
- canonical host

### 구조 개선

6. 지역 SEO 전략 재정의
- `전주 전용 사이트`인지
- `전국 사이트`인지
- 한 도메인에서 전국을 다룰지, 지역별 도메인으로 분리할지 먼저 결정 필요

## 7. 네이버 서치어드바이저 관점 판단

현재 네이버에 불리한 핵심 원인:

1. 사이트맵에 404 URL 포함
2. 비존재 URL이 200으로 노출되는 soft 404
3. 실배포와 로컬 설정 불일치 가능성

`사이트맵을 찾을 수 없습니다`가 한때 표시됐더라도, 2026-03-08 점검 시점의 실제 라이브 응답 기준으로는 파일 접근 자체는 정상입니다.  
따라서 문제의 본질은 `파일 부재`보다 `제출된 URL 품질과 오류 라우팅`에 가깝습니다.

## 8. 참고 메모

- 브라우저에서 `sitemap.xml`이 검은 화면처럼 보이는 현상은 XML 파일 자체 오류가 아니라 브라우저 확장 또는 렌더링 이슈일 가능성이 큽니다.
- 라이브 사이트 기준 사이트맵 파일은 정상적으로 내려오고 있습니다.

## 9. 최종 판정

현재 상태는 `배포 유지 가능` 수준은 되지만, `SEO 운영 가능` 상태로 보기는 어렵습니다.

판정:
- 운영 가능: `조건부`
- SEO 배포 적합성: `NO`

이유:
- soft 404가 치명적
- sitemap에 404 URL 포함
- 로컬/실배포 불일치 가능성 존재
